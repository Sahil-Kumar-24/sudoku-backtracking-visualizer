    How the algorithm works

    Recursive backtracking

    The solver always fills the first empty cell. It tries the digits 1 to 9 in order. A digit is accepted only if it does not already appear in that row, column or 3x3 box. After accepting a digit the solver calls itself for the next empty cell. If that call fails, the digit is erased (a backtrack) and the next digit is tried. If all nine digits fail, the function returns false and the previous cell is retried.

    solve(board):
  cell = first empty cell
  if there is no empty cell:
      return TRUE                  # base case: solved
  for digit = 1 to 9:
      if digit is safe in row, column, box:
          place digit
          if solve(board): return TRUE
          remove digit             # BACKTRACK
  return FALSE                     # caller must backtrack

    What the counters mean

    Recursive call
    One run of solve(). There is one call at the start and one more for every accepted digit, so calls = accepted placements + 1.
    Attempted placement
    One candidate digit tested in a cell, whether it was accepted or rejected.
    Accepted placement
    A candidate that passed the row, column and box check and was written to the board.
    Backtrack
    An accepted digit that was erased because the deeper calls could not finish the puzzle.

    Complexity analysis

    Let m be the number of empty cells (at most 81).

    Time complexity

    CaseTimeWhy
    BestO(m)Every first valid digit is correct, so there is no backtracking: m + 1 calls.
    WorstO(9m)The recursion tree is at most m levels deep and each cell branches into at most 9 digits.

    Work inside one call is constant for a 9x9 board: scanning for an empty cell costs at most 81 steps, and each of the 9 candidates is checked in at most 27 comparisons. So total time is (number of calls) x O(1) = O(9m) in the worst case.

    The check against the row, column and box prunes most branches early, so real puzzles need far fewer calls than 9m. The Stress test sample shows what happens when pruning helps very little: the search runs into the call limit.

    Space complexity

    O(m) extra space, which is at most 81 stack frames. Each recursive call adds one frame and the deepest chain is one call per empty cell. The board itself (81 numbers) is changed in place and never copied inside the recursion.

    For a fixed 9x9 board this is a constant, O(1). For a general n x n board it is O(n2).

    The step list that this page records for the animation is extra memory used only by the visualizer (capped at 50,000 steps). The algorithm does not need it.

    Solving generalised Sudoku on larger boards is known to be NP-complete, which is why no known algorithm avoids exponential worst cases.
